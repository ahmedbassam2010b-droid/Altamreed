# روابط الأكاديميات الفرعية للمدرسين

## ما أضافه الكود
- عند إنشاء مدرس من `teachers-admin.html` يُطلب اسم فرعي فريد مثل `ahmed-nursing`.
- يُحفظ `academySlug` في مستند المدرس، ويُنشأ مستند عام آمن في `academyProfiles/{slug}` لبيانات الهوية فقط.
- يستطيع المدرس تعديل اسم الأكاديمية والوصف والتخصص والشعار واللون من تبويب «هوية الأكاديمية».
- صفحة `academy.html` تعرض واجهة الأكاديمية، و`cloudflare/academy-router.js` يوجّه طلبات النطاقات الفرعية إلى هذه الصفحة دون تغيير `index.html` أو مسارات الدخول الحالية.

## إعداد النطاق والاستضافة المطلوب قبل التشغيل الفعلي
1. يجب أن يكون DNS الخاص بـ `bawabet-altamreed.com` على Cloudflare، مع تفعيل Proxy (السحابة البرتقالية) لسجل wildcard باسم `*` يشير إلى النطاق الأساسي.
2. أنشئ Cloudflare Worker من `cloudflare/academy-router.js`، ثم اربطه بالمسار `*.bawabet-altamreed.com/*`. اترك النطاق الأساسي و`www` خارج هذا المسار.
3. تأكد من أن Cloudflare SSL/TLS مضبوط على Full (strict) وأن النطاق الأساسي يعمل عبر HTTPS.
4. أضف النطاقات التي ستستخدم تسجيل الدخول إلى Firebase Authentication > Settings > Authorized domains. Firebase Auth لا يقبل افتراضًا أن كل النطاقات الفرعية مصرح بها بمجرد إضافة النطاق الأساسي؛ لذلك يجب اختبار نطاق كل أكاديمية أو اعتماد تسجيل دخول مركزي قبل التوسع.
5. انسخ `firestore.rules` إلى Firebase Console > Firestore Database > Rules ثم انشرها. رفعها إلى GitHub لا ينشرها تلقائيًا.
6. اختبر صفحة أكاديمية تجريبية، وقراءة `academyProfiles` العامة، وتعديل الهوية بحساب المدرس، ثم اختبر دخول طالب ومدرس على نطاق فرعي قبل الإعلان.

## ملاحظات مهمة
- إنشاء سجل الأكاديمية في Firestore لا ينشئ DNS أو شهادة HTTPS تلقائيًا.
- الروابط الفرعية لا تعمل بمجرد دمج الكود؛ يلزم إعداد Cloudflare Worker وDNS وFirebase Authorized Domains.
- صفحة الأكاديمية تستخدم روابط الدخول على النطاق الأساسي للمحافظة على مسارات الدخول الحالية. لا يتم نقل جلسة Firebase تلقائيًا بين النطاقات الفرعية والنطاق الأساسي.
- هذا التنفيذ لا ينشئ دومينًا مدفوعًا لكل مدرس؛ جميع الروابط تبقى تحت `bawabet-altamreed.com`.
