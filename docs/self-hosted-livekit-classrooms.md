# الفصول المباشرة ذاتية الاستضافة — بوابة التمريض

يعتمد التكامل داخل الموقع على **LiveKit Server مفتوح المصدر مستضاف على خادم تملكه وتديره بوابة التمريض**. لا يستخدم هذا المسار JaaS أو LiveKit Cloud أو Cloudflare RealtimeKit.

## المكونات

- LiveKit Server: نقل الصوت والفيديو ومشاركة الشاشة.
- Cloudflare Worker الحالي: التحقق من Firebase، عضوية الطالب، اشتراك المدرس، وإصدار رموز دخول قصيرة الصلاحية.
- Firestore: بيانات المحاضرات والعضويات.
- واجهة الموقع: كاميرا وميكروفون المدرس، مشاركة الشاشة، المحادثة، رفع اليد، وموافقة المدرس على المتحدثين.
- Redis غير مطلوب لعقدة بث واحدة. عند تشغيل عدة عقد لخدمة غرف مختلفة، يحتاج LiveKit إلى Redis؛ الغرفة الواحدة نفسها يجب أن تتسع على عقدة واحدة حاليًا.

## نموذج القاعة

- المدرس يملك صلاحية النشر (الصوت والكاميرا ومشاركة الشاشة).
- الطالب يدخل بصلاحية مشاهدة وإرسال بيانات المحادثة/رفع اليد، ولا يستطيع نشر الصوت أو الفيديو في البداية.
- عند موافقة المدرس على طلب رفع اليد، يقوم Worker بتحديث صلاحية الطالب عبر LiveKit RoomService.
- عند إلغاء الصلاحية، يوقف LiveKit نشر مسارات الطالب.
- لا نفتح كاميرات كل الطلاب تلقائيًا؛ هذا تصميم محاضرة كبيرة مع متحدثين معتمدين.

## متطلبات الخادم

هذه ليست خدمة مجانية غير محدودة. نحتاج VPS/خادمًا مخصصًا بعنوان IPv4 عام، ونطاقًا فرعيًا مثل `live.bawabet-altamreed.com`، وشهادة TLS، وسعة شبكة مناسبة. توصي وثائق LiveKit في إعدادات الإنتاج بشبكة 10Gbps أو أسرع، لأن حد الأداء يعتمد على المعالج وعرض النطاق. لا تعتبر 300 مشاهد مضمونين قبل اختبار حمل حقيقي من شبكات وأجهزة مختلفة.

لـ300 مشاهد متزامن، إذا كان متوسط الفيديو 1 Mbps فالنقل الخارج يقارب 300 Mbps، ويزيد مع الصوت والبروتوكول والذروة. يجب شراء نقل بيانات/سرعة مناسبة مع هامش احتياطي. لا تستخدم خطة Cloudflare Workers أو Firebase باعتبارها خادم الفيديو؛ Worker يصدر الرموز فقط.

## نشر خادم LiveKit

1. جهّز VPS Linux حديثًا بعنوان IPv4 عام، مع موارد شبكة قوية. لا تستخدم Cloudflare Worker أو Firebase لاستضافة الفيديو.
2. في Cloudflare DNS أنشئ سجلّي A:
   - `live` → عنوان IPv4 للخادم.
   - `turn` → عنوان IPv4 نفسه.
   واجعل السجلين **DNS only (السحابة الرمادية)**؛ حركة WebRTC وUDP يجب أن تصل مباشرة إلى الخادم ولا تمر عبر HTTP proxy.
3. استخدم مولّد LiveKit الرسمي على جهازك أو بيئة موثوقة:
   ```bash
   docker pull livekit/generate
   docker run --rm -it -v "$PWD:/output" livekit/generate
   ```
   أدخل `live.bawabet-altamreed.com` كعنوان LiveKit و`turn.bawabet-altamreed.com` كعنوان TURN. المولّد ينشئ ملفات Docker Compose وCaddy وLiveKit وRedis وملف تثبيت VM.
4. راجع الملفات الناتجة، واحفظ مفاتيح LiveKit في مكان آمن. لا ترفع ملفات الإعداد التي تحتوي أسرارًا إلى GitHub.
5. أنشئ الخادم Ubuntu، ثم استخدم ملف `init_script.sh` الذي ولّده LiveKit، أو Cloud-init الخاص بالمزود. دليل LiveKit الرسمي يثبت Docker وCompose وينشئ خدمة systemd باسم `livekit-docker`.
6. افتح المنافذ المطلوبة في جدار الخادم والمزود:
   - TCP 80 و443 لإصدار الشهادات وواجهة WSS/TURN-TLS.
   - TCP 7881 لاتصال WebRTC الاحتياطي.
   - UDP 50000–60000 لمسارات WebRTC.
   - UDP 3478 عند تفعيل TURN/UDP.
   - لا تفتح 7880 للعامة؛ اجعله خلف Caddy.
7. بعد ظهور شهادة TLS بنجاح، اختبر اتصال عميلين، ثم 10، ثم 50، ثم اختبارات حمل تدريجية. لا تبدأ بدعوة 300 طالب قبل قياس CPU وRAM وفقد حزم UDP وسرعة الرفع.
   
الطريقة دي مبنية على دليل LiveKit الرسمي للـVM، الذي يجهز Caddy وDocker وTURN/TLS تلقائيًا، بدل إعداد TLS يدويًا.

## إعداد Cloudflare Worker

Worker الحالي اسمه `bawabet-live-storage-api`. احتفظ بمتغيرات Firebase وR2 الموجودة، وأضف:

**Variables**
- `LIVEKIT_WS_URL=wss://live.bawabet-altamreed.com`
- `LIVEKIT_API_URL=https://live.bawabet-altamreed.com` (عنوان HTTPS الذي يمرر طلبات LiveKit Twirp عبر Caddy)

**Secrets**
- `LIVEKIT_API_KEY` — نفس المفتاح الموجود في إعداد LiveKit.
- `LIVEKIT_API_SECRET` — نفس السر الموجود في إعداد LiveKit.

لا ترسل هذه القيم في المحادثة ولا تضعها في مستودع GitHub. بعد ضبطها انشر Worker من Cloudflare.

## ملاحظات عن السعة

- حد الغرفة الواحدة يحدده أداء عقدة LiveKit التي تستضيف الغرفة، وليس عدد صفوف المدرس في Firestore.
- LiveKit يوجّه الغرفة الواحدة إلى عقدة واحدة في الوضع الموزع؛ إضافة عقد لا تقسم الغرفة نفسها تلقائيًا.
- زيادة عدد العقد تفيد في استضافة غرف متعددة وتوزيعها، لكنها لا تعني أن غرفة واحدة ستتوزع على كل العقد.
- اختبر 300+ اتصال مشاهدة متزامن على نفس المحاضرة قبل إعلان هذا الرقم كحد مضمون.

## ما لم يكتمل بعد

- لم يتم إنشاء VPS أو شراء نطاق/خدمة استضافة أو نشر LiveKit Server.
- لم يتم ضبط أسرار Worker أو نشر نسخة Worker الجديدة.
- لم يتم إجراء اختبار حمل 300 اتصال أو اختبار ميداني من أجهزة الطلاب.
- تسجيل المحاضرات غير مفعّل في هذه النسخة؛ يحتاج إعداد Egress وتخزين تسجيلات منفصلًا.
- واجهة الطلبات والموافقة على المتحدثين والمحادثة موجودة في الكود، ويجب اختبارها على خادم فعلي قبل الإنتاج.
